## Strict boundary
`dj_rezrxtion` defines **artist performance/brand, life-story intent and DJ trick sketches**. It is not a source of current `SongSpec`, `ProductionTimeline`, `ProjectRevision`, `SampleAsset`, music `RenderArtifact` or playback authorization.

**SARA_studio remains sole runtime/music authority** for song/project objects, playable artifacts and preservation. Import artist canon as creative input, never as a replacement project truth or automatically applied history mutation. No browser/cache/CAS-based truth.

## What can be automated
- At draft creation/review: read the linked latest canonical docs; validate Suno Lyrics ≤5,000 and Styles ≤1,000 exact Unicode codepoints; check hook repetition, no accidental unbracketed DJ/hype cue text, distinct arrangement and purpose.
- At actual studio execution: produce authorized beat-locked DJ events sourced from verified `SampleAsset` and stored on immutable revisions; verify physical artifacts and preserve non-target changes under appropriate P0–P3 tier.
- In proof: separately record text-valid / source-tested / integrated / executed / decoded / listened / creatively approved / release-ready. **Do not equate text prompting to a performed DJ scratch**.
